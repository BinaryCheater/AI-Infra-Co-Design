# Simulator gaps

Designs the mechanistic model could not match **without changing a measured parameter**, logged as
missing mechanisms per `notes/mechanistic_simulator_design.md` §4. Measured parameters come from
`calibration/spark-6951/contract.yaml` and are never fitted; structural choices are in
`agentic/sim/config/spark-6951-gb10.yaml` with the benchmark that justified each.

| # | Design / benchmark | Simulated vs measured | What is missing | Status |
|---|---|---|---|---|
| 1 | 4096³ GEMM, 128 × 256 × 16 tiles, S = 2, P = 1, β = 1 (spark-001, iteration 1): 9395.7 µs measured | G2 (L2 + DRAM only): 5057 µs (−46 %), critical path `barrier`/compute in every phase | **M3, shared-memory reads during compute.** Each k-step of the generated kernel issues 8 + 16 `ld.shared` per thread (393 KB per phase per block); at the measured 154 GB/s per SM that is 2.5 µs per phase against 1.8 µs of FMA. G2 has no shared-memory mechanism, so the phase is FMA-bound in the model and smem-bound on the card. | **After G3 (M3 + M4): 7414 µs (−21 %)**, critical path `smem` in 123 of 128 phases. The FMA pipe (1.8 µs/phase) and the `ld.shared` pipe (2.56 µs/phase at the measured 154 GB/s) overlap only partly on the card (3.3 µs/phase measured). What is missing is instruction issue: both pipes are fed by the same warp schedulers and each k-step's loads precede its FMAs, which §1 puts out of scope. Also open: whether B6's 154 GB/s is the LDS pipe's rate or the benchmark's dependent-chain limit (a B13-class LDS throughput benchmark with independent loads would say). Not fitted. |
| 2 | B8 cp.async latency vs tile size | depth 370 (from the 4 → 48 KB slope) reproduces the endpoints within 5 %; 8–32 KB are +9 % to +20 % slow | The per-SM copy rate is not constant in tile size (≈ 62 GB/s at 4 → 8 KB, 37 GB/s at 32 → 48 KB): a single outstanding-chunk window gives a straight line. Likely the issue side (cp.async instruction issue and address arithmetic per chunk, 1–12 instructions per thread) adding to the flow; needs a B8 variant that separates issue from completion. | logged; B8 test holds the endpoints at 5 % and the middle at 25 % |
| 3 | 4096³ waves | the measured run is 512 blocks on 48 SMs (10.7 waves); the simulator's breadth-first scheduler starts the last partial wave with 32 idle SMs | not a mismatch in itself, but the scheduler's dispatch order is unverified (B9 fixes capacity, not order) | a residency-order microbenchmark would confirm |
